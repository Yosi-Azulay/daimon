daimon v1.9.0

Local dev-server manager for 20+ frameworks — Angular / Nx / Next.js / Vite / Django / Rails / .NET / Flutter and more — with a TUI, a 127.0.0.1 HTTP API, a JSON CLI, and an MCP server for Claude Code.

Install

npm install -g daimon
# or
npx daimon init --auto

Quickstart (3 min)

  1. Run daimon init --auto in a workspace with any supported framework marker — nx.json, angular.json, next.config.*, vite.config.*, manage.py, Gemfile, a *.csproj, pubspec.yaml, or just a package.json with a dev script. Run daimon frameworks to see the full registry.
  2. Run daimon list to see discovered apps.
  3. Run daimon start <app> (or daimon up <profile> for the whole stack).
  4. Open the dashboard: daimon dashboard.

Stability tiers

Every surface below carries a tier (full contract in STABILITY.md):

  • frozen — the shape never breaks; changes are additive only. Guarded by golden-shape contract tests.
  • stable — breaks only with a major version bump and a migration note.
  • experimental — may change in any release (the v0.13 surfaces: report, env, ports, notifications, digest).

Config files are a special case: any config that ever loaded keeps loading, regardless of tier — unknown or legacy keys warn, never fail.

CLI reference

lifecycle

daimon start <name> [--with-deps] [--steal] frozen
Start an app. --steal overrides another agent's soft-lock.
daimon stop <name> [--steal] frozen
Stop an app. --steal overrides another agent's soft-lock. A name matching no app but a group stops the group (app-name precedence).
daimon restart <name> [--steal] frozen
Restart an app. --steal overrides another agent's soft-lock.
daimon test <name> [--failed] [--timeout <dur>] [--steal] [--json] stable
Run the app's own test suite once: resolves the runner (vitest/jest/pytest/go/cargo/dotnet or overrides.<app>.testCommand), parses failures with file:line + coverage, records the run in history. Exit 0 all pass, 1 failures, 2 timeout.
daimon up [<group>|<profile>] [--until serving|healthy] [--timeout 300s] [--steal] stable
Start a group or profile (or autoStart). Groups resolve first: depends-aware topo order + a "3/4 healthy" readiness summary. Profiles behave as before.
daimon down [<group>|<profile>] stable
Stop a group, a profile, or all apps. Groups resolve first and stop members in reverse depends order.
daimon mute <name> [--for <dur>] experimental
Mute OS notifications for an app (optionally for a duration). Persisted; shown in status and the dashboard.
daimon unmute <name> experimental
Lift a notification mute.
daimon run <name> <task> [--watch] [-- args...] stable
Run a discovered task.
daimon clean <name> [--deep] [--yes] stable
Remove build artifacts for an app.
daimon daemon start|stop|status|restart|attach|install-service [--detach] [--headless] frozen
Manage the daimon daemon.

queries

daimon list [--tag <name>] [--workspace <label>] [--group <group>] [--full|--compact] [--stream] [--explain] frozen
List apps. Compact by default; --full for v0.4 shape; --stream for NDJSON; --explain wraps with _meta (searchRoots, scanned, rejected, suggestion).
daimon status <name> [--full|--compact] | --group <group> frozen
Get the current status of one app (compact by default), or of a whole group with --group.
daimon errors <name> [--since 2m] [--since-last] [--client <id>] [--structured] [--full|--compact] | --group [<group>] frozen
Get deduplicated errors for an app. Compact by default ({file,line,col,code,message}). --group (no name) groups all apps' errors by stack fingerprint.
daimon events [--since 1h] [--app <name>] [--stream] frozen
Get the event log. --stream emits NDJSON until SIGINT.
daimon logs <name> [--tail N] [--since 30s] [--level <lvl>] [--grep <regex>] [--stream] | --group <group> frozen
Recent log lines for an app. --level filters by classified level; --grep filters server-side (regex, ≤512 chars); --stream follows the live tail as NDJSON; --group merges a group's tails.
daimon search <query> [--app <a>] [--since <dur>] [--kind logs|errors|events] [--limit N] stable
Full-text search over everything daimon has seen: log lines, errors, and events. Compact JSON hits {kind,app,ts,snippet,ref}.
daimon test-history <name> [--flaky] [--limit N] stable
Recent test runs for an app (totals, exit codes, gitHead, failures). --flaky lists tests that flipped pass↔fail ≥3× at the same gitHead.
daimon history <name> stable
Summary metrics (uptime%, restarts, compile p50/p95, top errors).

agent verbs

daimon wait <name> [--until serving|healthy|stopped|error] [--timeout 120s] frozen
Block until app reaches the given state.
daimon ensure <name> [--until serving|healthy] [--timeout 180s] stable
One-call: start if needed, block to target state, return terminal state. Idempotent.
daimon ensure-up <profile> [--until serving|healthy] [--timeout 300s] stable
One-call: cascade-start every app in the profile and wait for each to reach target.
daimon overview [--workspace <label>] [--profile <name>] [--budget <tokens>] stable
Decision-ready snapshot: totals, byStatus, needsAttention (with first parsed error), recentlyChanged. First call in a session. --budget caps the response size for agents; overflow collapses to _meta.omitted.
daimon focus <name> [--until serving|healthy|stable] [--timeout 180s] stable
One round-trip subscribe-then-act: streams NDJSON of status/error/url events for one app until target state or timeout. Designed for agents.
daimon try-fix <name> [--until serving|healthy] [--timeout 180s] stable
Composite: run doctor --auto-fix on permitted rules, restart the app, wait for target, return {before,after,fixed,stillFailing}. Never edits user source.
daimon orchestrate <profile> [--goal serving|healthy|stable] [--timeout 300s] [--dry-run] [--budget <tokens>] stable
Bring up a whole profile in one call: cascade-start, wait for goal, run ONE try-fix round on stragglers. Returns {profile, goal, perApp, totalMs, allReached}. --dry-run reports planned order only. Designed for agents.
daimon context <name> [--budget <chars>] stable
Agent context pack: status/framework/uptime, top error groups, last crash, last test run, compile stats, suspect commits, locks — one call instead of six.
daimon audit [--agent <id>] [--app <name>] [--since 2h] [--limit 100] [--json] experimental
Query the audit trail: who did what, when. Derives { ts, agent, action, app, changedKeys, remote } rows from audit.log + audit.log.1. Filters compose (AND); newest first.
daimon agents [--json] stable
Roster of agents touching this daemon: id, last-seen, action counts, held soft-locks, contention. Derived at query time from the audit log + live registry + lock manager.
daimon handoff <app> <agentId> stable
Transfer the soft-lock on <app> to another agent.
daimon profiles suggest [--since 30d] [--min 5] stable
Suggest profile candidates from recurring co-starts.
daimon ci start <profile> [--until ready|healthy] [--timeout 5m] [--json] stable
CI helper: start a profile and block until all apps are healthy. Designed for GitHub Actions / Jenkins steps.

introspection

daimon report [--since 24h|7d] [--app <a>] [--workspace <label>] [--md] experimental
The digest: per-app uptime, errors (new/recurring/resolved), test pass-rate + flakiest, compile p50/p95 + regressions, crashes/storms, agent activity, env changes.
daimon export [--since 7d] [--app <a>] [--format json|md|csv] [--out <file>] experimental
One-way carry-out bundle: events, error groups, test runs, compiles, crashes (bounded tails), and the report in one versioned envelope (schemaVersion 1). JSON canonical; --format md paste-ready; --format csv flat rows.
daimon sessions [--since 7d] [--json] | show <id> [--json] experimental
Walk history by daemon-uptime slice. Each session is DERIVED from the daemon-start/daemon-stop lifecycle: id (s-<startMs>), start/end, duration, endedCleanly, current, apps touched, error/test/compile counts. `show <id>` expands one slice into a digest (apps started/stopped, error groups, test runs, compiles p50/p95, crashes, env changes) — each block degrades to a note.
daimon env <name> [--use <file>] | diff <name> [--from <ts>] [--to <ts>] experimental
Env-file awareness: convention files (found/missing), key names, snapshot age; `env diff` shows files/keys added/removed/changed between spawns. --use sets the active env file (pre-v0.13 behavior). Values are NEVER shown.
daimon why <name> stable
One-shot forensics: status, last crash (exit code + final log lines), grouped 24h errors, regressions, restart-storm state, suspect commit, matching doctor findings.
daimon why-empty stable
Explain why `daimon list` is empty: configured searchRoots, scanned/rejected counts, suggested next step.
daimon discover stable
Run discovery read-only. Prints _meta: searchRoots, scanned, rejected per folder, suggestion.
daimon frameworks stable
List framework profiles (built-in + custom): detection markers, command, which apps matched, rejection stats.
daimon tasks <name> stable
List discovered non-serve tasks.
daimon snapshot <name> stable
Write a snapshot of app state to ~/.daimon/snapshots.
daimon record stable
Toggle session recording.
daimon replay <session.jsonl> [--speed N] stable
Replay a recorded session.
daimon doctor [--auto-fix] [--dry-run] [--self] stable
Sanity-check config + env. --auto-fix repairs orphan daemon, stale lock, missing search root, corrupt history db. --self checks daimon's own metrics.
daimon ports experimental
Port map: app → port → source (pinned|pool|announced) → pid, plus foreign holders of pool/pinned ports.
daimon top [--json] experimental
Live resource table: app → pid → rss → cpu → uptime, sorted by RSS. Watch-and-warn only — daimon never kills.
daimon free-port <port> [--force] stable
Diagnose / free a port.
daimon self stable
Print daimon's own runtime metrics (pid, version, uptime, rss, heap, event-loop lag, history-db p95).
daimon dashboard stable
Open the dashboard in your default browser, scoped to the current cwd.
daimon timeline [--since 7d] [--app <name>] [--kinds status,error,warning,lint,bundle,task] stable
Print a unified chronological event timeline.

config

daimon pin-health <name> [--accept] [--path <p>] stable
Show the auto-discovered health-probe path for an app; --accept persists it as overrides.<name>.healthProbePath in daimon.config.json and soft-reloads. Default behaviour is opt-in: nothing is written without --accept.
daimon config validate [<path>] experimental
Validate a daimon config against the known-key schema: unknown keys warn with the nearest valid name; malformed values listed; group checks (unknown apps, autoStart overlap, profile collisions). Exit 0 with warnings, 1 on errors.
daimon export-config [--redacted] frozen
Emit the active config to stdout. --redacted replaces apiToken with "<redacted>" and rewrites home paths to ~/...
daimon init [--force] [--auto] stable
Create a daimon config in cwd; --auto picks safe defaults (no prompts) for workspaces with nx/angular/vite markers.
daimon completion <bash|zsh|fish|powershell> stable
Emit a shell completion script for the given shell.
daimon workspaces list|add [path] [--label <name>] | rm <path> | show [path] stable
Manage the workspace registry (searchRoots).

claude

daimon claude install|update|uninstall|status [--skill] [--commands] [--agent] [--all] [--dir <path>] [--yes] stable
Install/update Claude Code integration artifacts.

plugin

daimon plugin list|show <name>|validate <path> stable
Manage plug-ins (Plugin API v1): list, show one, validate a file offline.
daimon plugins [--json] experimental
List loaded plug-ins: name, apiVersion, status (active|disabled|load-error), hooks, error.

Experimental sub-keys inside stable parents: notifications.kinds / notifications.quietHours / notifications.batchMs and webhooks[].digest (v0.13); logs.storm (v1.2).

Highlights:

  • searchRoots — array of paths (or {path, label}) to scan for projects.
  • autoStart — apps to start when the daemon launches.
  • profiles — named sets of apps for daimon up <profile> / daimon ci start <profile>.
  • healthProbe — toggle and shape the per-app health probe.
  • webhooks — outbound notifications: [{url, events?, headers?, filter?, apps?, digest?}] with Slack/Discord shaping; apps scopes an entry to specific apps (v0.11); digest: "HH:MM" sends the daily report (v0.13).
  • frameworks — custom framework profiles (v0.11): data-only rows [{id, detect, command, readiness?, url?, errorParser?}] checked after the built-in registry. Detection markers and regex strings only — never loaded code.
  • overrides.<app> — per-app port / command / env / webhooks / testCommand (v0.12: explicit test runner, always wins) / logIndex (v0.12: opt this app's log lines out of search indexing), plus tuning knobs like compileRegressionFactor.
  • history — SQLite retention controls (also prunes v0.12 test runs, crash reports, and the search index).
  • tests — { flakyThreshold: 3 } (v0.12): pass↔fail flips at the same git head before a test is flagged flaky.
  • restartStorm — { perHour: 20 } (v0.12): unrequested exits per hour before a single restart-storm event fires.
  • search — { logIndex: true } (v0.12): global default for per-app log-line indexing; errors/events are always indexed.
  • ports — { pool: "4200-4299" } (v0.13): opt-in auto-assignment; only frameworks whose registry row documents portFlag/portEnv participate.
  • logs.storm — { multiplier: 10, windowSec: 60 } (v1.2): tunes log-storm detection (a sustained spike vs the app's own lines/min baseline). Optional; detection always runs with the defaults and emits only self-events — the log-storm OS-notification kind is a separate opt-in via notifications.kinds. Custom framework profiles may also declare logLevelPatterns [{pattern, level}] rows (v1.2) for log-level classification — validated data, first match wins, invalid rows are ignored with a warning.

FAQ

Does daimon edit my code?
No. Daimon only touches ~/.daimon/* and (if you opt in) the local daimon.config.json. daimon doctor --auto-fix repairs daemon state, never source.
Is it safe to run two Claudes against one daemon?
Yes — every CLI call sends an X-Daimon-Agent header and the daemon enforces a 30-second per-app soft-lock so two agents don't fight. Pass --steal to override.
How do I get a notification when an app errors?
Configure a webhooks entry pointing at Slack/Discord, or call daimon_notify_on_error from MCP.
Can I use daimon in CI?
Yes — daimon ci start <profile> --until ready --timeout 5m --json returns a structured report and exits 2 on timeout. See the CI integration guide.
